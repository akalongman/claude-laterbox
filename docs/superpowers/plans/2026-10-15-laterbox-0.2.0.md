# Laterbox 0.2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rename the plugin `later` to `laterbox`, move it to the repository root, make the queue file a setting, and make the bash engine run on stock macOS and cheaply under Git Bash, proven by a three-OS CI workflow.

**Architecture:** One bash engine (`scripts/later.sh`) stays the only writer of the queue; every entry point (session-start hook, hooks module, skill, terminal command) reaches it. The engine gains a single name-resolution rule, a pure-bash JSON encoder and parser, a `mkdir` lock fallback, local-time arithmetic without `date -d`, and a fixed process count. The hooks module only threads the new setting into each engine run.

**Tech Stack:** bash (3.2 compatible), git 2.31+, POSIX tools; TypeScript hooks module on the Claude Code mod API (floor 2.1.296); GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-15-laterbox-0.2.0-design.md`

## Global Constraints

- Plugin `laterbox`, display name `Laterbox`, marketplace `akalongman`, repository URL `https://github.com/akalongman/claude-laterbox`, license MIT.
- The slash command stays `/later`; output lines keep the prefix `later:`; the terminal command stays `later`; the `LATER_*` variables keep their names; state stays under `${XDG_CACHE_HOME:-$HOME/.cache}/later/`.
- Settings are named `laterbox.<key>` in every user-visible string: `laterbox.rewrite`, `laterbox.terminal`, `laterbox.file`. The skill is `laterbox:notes`.
- Default queue file `LATER.local.md`; the heading written on creation stays `` # Parked notes (`/later`) ``.
- The stored setting lives at `${XDG_STATE_HOME:-$HOME/.local/state}/later/queue-file`.
- The engine runs on bash 3.2: no `mapfile`/`readarray`, associative arrays, `${v,,}`/`${v^^}`, `printf '%(...)T'`, `EPOCHSECONDS`, `local -n`, `|&`, `;&`, negative array indices.
- The engine needs only bash, git 2.31 or later, and tools present on Linux, stock macOS and Git for Windows. No `jq`. `flock` optional. No GNU-only flags: `date -d`, `chmod --reference`, `find -xtype`, `mv -T`, `readlink -f`; `sha1sum` only with a `shasum -a 1` fallback.
- Claude Code floor: 2.1.296.
- TypeScript: the rules of the existing module (4-space indent, 120 columns, single quotes, strict types, no `any`, readonly data, annotated exported returns). Shell: `shellcheck` clean.
- No em or en dashes in any text, code comment, message or commit.
- Prose in the repository is agent-neutral: it names no assistant-specific tool.
- Work stays on `main`; never create, switch or rename a branch. Commits are signed by the repository's configuration (never override signing), path-limited: `git add <paths> && git commit -m "<title>" -- <paths>`, imperative title under 72 characters, no trailers. Verify each with `git show --stat HEAD`.
- No outward step (rename on GitHub, push, tag, portal) is part of this plan.

## Review Focus

1. A queue file name holding a space, a leading dash or non-ASCII letters (`Later notes.md`, `-notes.md`, `შენიშვნები.md`): add, list, done, `all` and the stored copy all work with it. Test in Task 3.
2. A project folder whose path holds a space: add, list, done, session-start and `all` work. Test in Task 9.
3. A stored copy that is empty, unreadable or holds an unusable value: the default is used and nothing breaks. Test in Task 3.
4. A queue saved with CRLF and rewritten by `done` or `drop`: every line the engine did not change stays byte-identical. Test in Task 8.
5. Hook input whose `cwd` key also appears inside a nested object before the top-level one, with escaped backslashes (a Windows path) and `\u` escapes: the top-level value is used, decoded. Test in Task 5.

### Task 6: A lock that works without flock

**Files:**
- Modify: `scripts/later.sh` (`with_lock`), `tests/later.test.sh`

**Interfaces:**
- Produces: `with_lock <file> <command...>` keeps its signature. It uses `flock` when present unless `LATER_NO_FLOCK=1` (a test seam, documented beside `LATER_NOW`). ### Task 7: Local-time arithmetic and a fixed process count

**Files:**
- Modify: `scripts/later.sh`, `tests/later.test.sh`

**Interfaces:**
- Produces:
  - `load_clock`, called once per run before dispatch. One `date` call sets `NOW_EPOCH` (seconds), `NOW_MIN` (civil minutes of the local wall clock) and `NOW_STAMP` (`YYYY-MM-DD HH:MM`, local). With `LATER_NOW` it formats that instant: `date -d "@$LATER_NOW"` where it works, else `date -r "$LATER_NOW"`. The `date -d` line ends in the comment `# gnu-date-probe` (Task 9's static check looks for it).
  - `civil_days <year> <month> <day>` sets `REPLY` to days since 1970-01-01 by the days-from-civil algorithm (H. Hinnant), base 10 forced.
  - `stamp_minutes "<YYYY-MM-DD HH:MM>"` sets `REPLY` to `civil_days * 1440 + hour * 60 + minute`, or 0 when the date is not real (month 1 to 12, day within the month with leap years, hour 0 to 23, minute 0 to 59).
  - `age_label <minutes>` sets `REPLY` to `undated` (for 0), `today`, or `<N>d` with N = (`NOW_MIN` - minutes) / 1440.
  - `clip <text> <width>` sets `REPLY`.
  - Rows from `open_notes` carry civil minutes in their third field, where epochs were.
  - `STATE_DIR` stays `.../later/v2`, and a state file keeps its two lines (epoch of the last display, epoch of the last digest) and gains a third, the `NOW_MIN` of the last display. A note is new when its minutes are at least the last display's minutes: line 3 when present, else line 1 converted as `NOW_MIN - (NOW_EPOCH - line1) / 60`. So 0.1.0 state keeps working and keys do not change (spec R5.4). The digest test stays `NOW_EPOCH - digest >= DIGEST_DAYS * 86400`.
  - `cmd_add` stamps with `NOW_STAMP`.
  - No function's result is taken through `$(...)` per note or per row. A command's process count does not depend on the number of notes.
